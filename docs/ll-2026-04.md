# LL-2026-04, requirement by requirement

Fannie Mae Lender Letter LL-2026-04 was issued 8 April 2026 and took effect
8 August 2026. It applies to seller/servicers using AI or ML in loan origination,
underwriting, servicing or quality control. Enforcement is repurchase risk:
loans failing seller/servicer guide requirements can be put back to the lender.

This document maps each requirement to where Custody satisfies it, and — more
usefully — states plainly where it does not. **Custody is a library, not a
compliance programme.** Several of the letter's obligations are organisational
and no software can discharge them.

Read this alongside the letter itself rather than instead of it.

---

## What Custody does

| Requirement | Where | Notes |
|---|---|---|
| Per-decision record: **principal** | `ledger.Decision` | The authenticated actor the caller supplies when opening the decision. Required, no default. |
| **model** | `Decision.call(model=...)` | Recorded on the AI record; `null` on human-review records, which is what they are. |
| **endpoint** | `Decision.call(endpoint=...)` | Defaults to `anthropic:messages:{model}` when not given, so it is never silently empty. |
| **redacted prompt** | `redact.redact_value` | Applied at write time, not by the caller. Patterned PII (SSN, phone, email, DOB, long account numbers) plus caller-declared identifiers. The loan number is deliberately preserved — it is the required query key. |
| **response treatment** | `verify.gate` | `pass` / `review` / `reject`, produced by deterministic checks. Not a label somebody types. |
| **policy version** | `Ledger(policy=...)` | Stamped on every record from the ledger, so it cannot vary per call by accident. |
| **decision outcome** | `Decision.commit(outcome=...)` | What was written downstream. `null` when a decision was rejected or routed rather than committed — nothing *was* written, and inventing a value to fill the field would be the lie. |
| **timestamp** | automatic | UTC, millisecond precision, taken when the decision opens. `completed_at` records when it closed. |
| **Append-only** | `store.Store` | SQLite triggers abort any `UPDATE` or `DELETE` against the ledger table. Enforced by the database rather than by convention. |
| **Signed** | `chain.seal` | Ed25519 over each record's hash. Records are additionally hash-chained, so editing or removing one is detectable without the key. |
| **Queryable by loan, date, model, principal** | `Store.query` | All four are indexed columns; the letter's four dimensions are the four things this table answers quickly. |
| **Human oversight below confidence thresholds** | `verify.check_confidence` + `Ledger.human_review` | Under the floor routes to a person rather than rejecting — not being sure is not the same as being wrong. The person's decision is itself a chained record naming who, when, and what they did. |
| **Records an examiner can inspect** | `examiner.packet` | Per-loan chain of evidence carrying the records, the public key and the verification result, so the recipient checks it without access to the lender's systems. |

## What Custody does not do

Stated plainly, because a vendor implying coverage it does not have is exactly
the problem this letter exists to address.

| Requirement | Status |
|---|---|
| **Inventory of AI models and tools** in origination, underwriting, servicing and QC | **Not covered.** Custody records the models it is asked to wrap. It has no view of models it never sees, and an inventory assembled only from what happened to be instrumented is worse than none — it looks complete. |
| **Documented governance programme with executive ownership** | **Not covered.** Organisational, not technical. |
| **Model documentation** — purpose, data sources, training-data lineage, validation methodology, use limits | **Partial.** Purpose is recorded per decision and policy version is stamped on every record. Training-data lineage and validation methodology belong to whoever built or bought the model. |
| **Monitoring for drift, bias and error rates, reported to a governance committee** | **Not covered.** The ledger is the substrate such monitoring could be built on — every verdict, override and human correction is queryable — but Custody does no bias or fair-lending testing and makes no disparate-impact claim. That is a separate obligation with mature vendors already in it. |
| **Enforceable vendor contracts** | Not software. |

## Two design decisions worth arguing with

**Committing over a rejection is permitted, and recorded as an override.**
A gate that makes an override impossible gets bypassed entirely, and then
nothing is recorded at all. `disposition` distinguishes `committed` from
`committed_over_rejection`, so an override is visible to anyone reading the log
rather than absent from it.

**Rejected decisions stay in the packet.** Filtering them out would produce a
cleaner-looking artifact and a false one. An audit trail that shows only the
successes is a brochure.

## Disclaimer

This is engineering documentation, not legal advice. Custody does not certify
compliance with LL-2026-04 or anything else. It produces records; whether a
given lender's programme meets the letter's requirements is a question for that
lender and its counsel.
